Сбор логов проводим со следующих сервисов:
- Shop API
- CRM API
- MES API

Уровни логов для прода:
FATAL (все ошибки приводящие к выходу из строя сервиса)
ERROR (обработка ошибок, запись в лог, если возможно исправление, код с обработкой ошибки пишется заранее)
INFO (событие старта сервиса, действие пользователя и операторов)

Уровни логов для дева:
FATAL
ERROR (ошибки приводящие к исключиниям)
WARN (ошибки не приводящие к исключиниям)
INFO
DEBUG ()
TRACE (тотальное логирование любого изменения состояния внутри микросерсов, включается такой режим выборочно)

Во всех логах отображаем такие атрибуты:
- время
- источник (имя сервиса, имя компонента, имя функции)
- описание события
- состояние переменных (все что поступало в функцию, например: userUID, orderUID и пр.)

Мотивация:

Крайне важно логировать события в программной системе, это позволяет устранить 
ошибки которые неизбежно присутсвуют в коде. На данном этаме устраняются ошибки в бизнес-логике, что очень важно 
для любого коммерческого предприятия.

Предлагаемое решение:

Схема логиирование на диаграмме https://drive.google.com/file/d/1KkKh1N7MO1mFQXVrVV4usIJTOUttsjJR/view?usp=sharing
Предлогаемая схема на стеке ELK. Для каждого сервиса создается свой индекс в ElasticSearch. 
Время жизни лог записи устанавливается 30 дней. В Kibana настраивается дашборды отдельные по каждому сервису, 
а также сводная дашборда. Ни в коем случае не храним в логах чувствительную информацию. 
Доступ в логам имеют только разработчики.

Алертинг настраивается с помощью системы мониторинга
Поиск аномалий осуществляется средствами мониторинга
