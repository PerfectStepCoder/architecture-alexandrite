Мотивация: 

Рассматриваемая программная система кампании "Александрид" имеет достаточное количество сервисов, 
которые взаимосдествуют друг с другом, для внедрения полноценной системы мониторинга. Особенно стоит отметить, 
что в текущей системе отсутсвует сбор бизнес метрик.

Выбор подхода к мониторингу:

В данном проекте я буду использовать все виды мониторинга, а именно:
- RED для сервисов CRM и Shop
- USE для микровисов по расчету стоимости ювелирных изделий по 3D моделям
- «Четыре золотых сигнала» для всех микрсервисов которые предоставляют API

Список метрик для отслеживания:
- Number of message in flight in RabbitMQ (тут мы отслеживаем количество заявок на расчет стоимости ювелирных украшений)
- Number of requests (RPS) for internet shop API (нагрузка на магазин)
- Number of requests (RPS) for CRM API (нагрузка на CRM)
- Number of requests (RPS) for MES API (нагрузка на MES API)
- Number of requests (RPS) per user for internet shop API (нагрузка на API)
- Response time (latency) for MES API (важная метрика показывающая как долго расчитывается цена по 3D модели)
- Number of connections for shop db instance (количество соеденений с БД, если показатель будет высоким тогда потребуется создавать кластер БД)

План действий:
1) Запуск сервиса Prometheus для сбора и хранения метрик
2) Внедрение экспортеры в микросервисы с которых будем собирать метрики
3) Развертывание Grafana
4) Настройка Alerts Manager (особенно важно ставить алерты на метрики связанные с обработкой заказов)

Показатель насыщенности я ставлю на инстансах CalulatePrice3D (которые расчитывают стоимость ювелирного изделия по 3D модели),
в случае превышений порогового значения в 90% запускаем новый инстанс данного микросервиса
