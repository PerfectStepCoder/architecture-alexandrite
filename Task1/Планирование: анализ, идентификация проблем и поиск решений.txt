
В текущей реализации системы обнаружены следующие проблемы:

- MES в части расчета стоимости ювелирного украшения по 3D моделям имеет крайне низкую производительность
- MES API работает под большой нагрузкой (выпоняет задачи внутри кампании "Александрит",
  а также выпоняет задачи строних пользователй API)
- Отсутсвуют бекапы баз данных, это влияет на надежность работы системы
- Используется ручное тестирование перед выкаткой на дев
- Многие сервисы не масштабированы

Пути решения обнаруженных недостатков:

- Выделить из продукта MES модуль расчета стоимости ювелирного украшения по 3D моделям в отдельных микросервис (CalulatePrice3D)
- Создать несколько инстансов микросервиса CalulatePrice3D подключить их к очереди RabbitMQ
- Подключить систему мониторинга, в частности размер очерей задач на расчет стоимости ювелирных украшений, при необходимости развернуть новые инстансы CalulatePrice3D
- Выделить отдельный инстанс MES API для стороних пользователей данного API (при увеличении нагрузки масштабировать этот сервис и закрыть их Gateway API)
- Реализовать репликацию во всех БД
- Реализовать автоматические скрипты тестирования
- Анализ дашбордов мониторинга, увеличить количество инстансов тех сервисов системы которые показывают высокие показатели латенси и насыщения при выскоких показателей RPC.

Самые важные задачи и их приоритет:
1) Выделить из продукта MES модуль расчета стоимости ювелирного украшения по 3D моделям в отдельных микросервис (CalulatePrice3D)
   Причина: жалобы пользователей системы, уходят клиенты из-за долгого ожидания выпонлнения заказов. Производиство справляется с нагрузкой, но хромает имеено расчет стоимости 3D моделей
2) Создать несколько инстансов микросервиса CalulatePrice3D подключить их к очереди RabbitMQ
3) Реализовать автоматические скрипты тестирования
   Причина: пользователи уходят, мы не можем быстро доставлять новые фичи для них
